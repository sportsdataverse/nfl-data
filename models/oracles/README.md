# Converted upstream oracles (committed fixtures)

Small, committed exports of upstream R model objects that this repo's gates and
model writeups compare against. They are **fixtures, not artifacts**: nothing here
is published, and nothing here is regenerated by a retrain. Each was exported once
from the upstream R object and is pinned to the source commit named below.

The larger converted boosters (`fd_model.ubj`, `xpass_model.ubj`, …) are NOT here —
they live outside the repo at `validate.ORACLE_DIR` because of their size. These
four files are committed precisely because they are small enough that the gate and
the docs should not depend on a machine-local path.

| file | bytes | what it is |
|---|---:|---|
| `fg_model_grid_nfl4th.csv` | ~11 K | nfl4th FG GAM make-probability over its full grid |
| `dakota_gam_terms.csv` | ~59 K | nflfastR `dakota` GAM partial-effect curves |
| `dakota_gam_intercept.txt` | 20 | that GAM's intercept |
| `dakota_gam_check.csv` | ~1.4 K | 25 `predict.gam` values that pin the interpolation |

## `fg_model_grid_nfl4th.csv`

- **Source**: `nflverse/nfl4th`, `data-raw/fg_model.Rdata` (object `fg_model`), repo
  commit `aca8c66fee105c1e5355c0daf962f64d4353e42b` (master, 2026-08-06).
- **What it is**: `mgcv::bam(sp ~ s(yardline_100, by = interaction(fg_model_roof)) +
  fg_model_roof)`, fit on 10,694 attempts, scored with `type = "response"` over the
  full `yardline_100 1..99 x fg_model_roof {00,01,10,11}` grid → 396 rows.
- **Columns**: `yardline_100`, `fg_model_roof` (`"RE"`: first digit roof — 1 outdoors,
  second digit era — 1 for season >= 2020), `prob` (GAM make probability).
- **Read this before comparing**: the grid spans all 99 yardlines in all four
  roof/era cells, but real FG attempts occupy only ~192 of those 396 cells. The GAM
  extrapolates its spline into cells that were never attempted; a monotone
  step-function booster cannot follow it there. Scope any correlation to attempted
  cells and report the full-grid number separately — see `docs/models/fg.md`.

## `dakota_gam_*`

- **Source**: `nflverse/nflfastR-data`, `models/dakota_model.Rdata` (object
  `dakota_model`), repo commit `606b786e72619bb1578f7429ffffc4bac731cf4e`
  (master, 2026-07-10). It is the model the (now-defunct) nflfastR `add_dakota()`
  downloaded at runtime; nflfastR's current `calculate_stats()` does not ship dakota
  ("not implemented at the moment", `data-raw/nfl_stats_variables.R`).
- **What it is**: `mgcv::gam(target ~ s(cpoe) + s(epa_per_play), weights = weight)`,
  n = 377 weighted player-season rows. `target` is next-season adjusted EPA/play, so
  dakota is a *forecast* of future efficiency, not a description of the current season.
- **Format**: `dakota_gam_terms.csv` is `predict(..., type = "terms")` evaluated on a
  1-D grid per smooth with the other term held at 0 — `term` in
  {`cpoe`, `epa_per_play`}, `x` the input value, `f` that term's partial effect.
  Because the model is purely additive, `dakota = intercept + f_cpoe(cpoe) +
  f_epa(epa_per_play)`, so linear interpolation on these two curves reproduces
  `mgcv::predict.gam` exactly to floating-point noise.
- **The pin**: `dakota_gam_check.csv` holds 25 `predict.gam` values at random
  in-domain points. `tests/test_dakota_gate.py` asserts the interpolation reproduces
  them to < 1e-4 (measured max error 8.0e-06). If that assertion ever fails, the
  interpolation — not the fixture — is wrong.
- **Domain**: the fit's own range is `cpoe` [-14.1, 8.0] and `epa_per_play`
  [-0.29, 0.39]. The exported grids extend past that (`cpoe` [-40, 40],
  `epa_per_play` [-2, 2]); values outside the fit range are spline extrapolation and
  should be read as such.

## Re-exporting

Both exports are a few lines of R (`mgcv` only; no nfl4th/nflfastR install needed —
the `.Rdata`/`.rds` files are fetched directly from the source repos):

```r
load(url("https://github.com/nflverse/nfl4th/raw/master/data-raw/fg_model.Rdata"))
grid <- expand.grid(yardline_100 = 1:99,
                    fg_model_roof = levels(fg_model$model$fg_model_roof))
grid$prob <- as.numeric(predict(fg_model, newdata = grid, type = "response"))
write.csv(grid, "fg_model_grid_nfl4th.csv", row.names = FALSE)
```

Re-export only to pick up a genuine upstream model change, and update the commit
SHAs above when you do — a fixture whose provenance line is stale is worse than no
fixture.
